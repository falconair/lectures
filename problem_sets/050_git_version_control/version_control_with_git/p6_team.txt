PROBLEM 6
Practises: working with a server: git init --bare, git remote, git push, git clone, git fetch
and git pull.

Work on the course server: log in with ssh, then do the steps below there.

Task: play two people who share a project through a server. The server is an ordinary folder.
  1. Make your own repository, mine, in a folder p6_team: type these commands.
         # make the folder p6_team; -p also makes the folders above it
         mkdir -p ~/problem_sets/050_git_version_control/version_control_with_git/p6_team

         # go into it
         cd ~/problem_sets/050_git_version_control/version_control_with_git/p6_team

         # copy the folder starter as mine; -r (recursive) copies everything inside it, folders and all
         cp -r /opt/lectures/problem_sets/050_git_version_control/version_control_with_git/starter mine

         # go into mine
         cd mine

         # make this folder a repository: git keeps the history in a hidden folder, .git
         git init

         # put every file on the stage (. means this folder)
         git add .

         # save what is on the stage in the history, with a message (-m)
         git commit -m "Starting point"

  2. Make the server, a repository with no working folder; connect mine to it, and push:
         # the server: a repository with only the history and no working folder (--bare)
         git init --bare ~/problem_sets/050_git_version_control/version_control_with_git/p6_team/server.git

         # tell mine about the server, under the name origin
         git remote add origin ~/problem_sets/050_git_version_control/version_control_with_git/p6_team/server.git

         # send main to the server; -u remembers where it goes, so next time git push is enough
         git push -u origin main

  3. Be your colleague Maya. Clone the server into a folder maya, and tell git you are Maya there
     (without --global, so it applies to that folder only):
         # up one folder, to p6_team
         cd ..

         # Maya's copy of the project, with all its history, in a new folder maya
         git clone server.git maya

         # go into maya
         cd maya

         # who Maya is: in this repository only, because there is no --global
         git config user.name "Maya"
         git config user.email "maya@example.com"

     With nano, write a README.md. Commit it, and git push.
  4. Be yourself again: go back to mine, ask the server what is new, look, and bring it in:
         # back to your own repository
         cd ../mine

         # ask the server what is new; your files do not change
         git fetch

         # git now knows that your main is behind the server's
         git status

         # fetch and merge: Maya's README arrives in your folder
         git pull

To check your work, type these three commands:
    cd ~/problem_sets/050_git_version_control/version_control_with_git/p6_team/mine
    git log --oneline --graph --all
    git remote -v

They should print (your hashes will differ, and your user name is in the paths):
    * 85a24c7 (HEAD -> main, origin/main, origin/HEAD) Add a README
    * fe12766 Starting point
    origin	/home/shahbaz/problem_sets/050_git_version_control/version_control_with_git/p6_team/server.git (fetch)
    origin	/home/shahbaz/problem_sets/050_git_version_control/version_control_with_git/p6_team/server.git (push)

NOTES
- Before your first commit on the server, tell git who you are: type the three git config commands
  from section 1 of the lecture (user.name, user.email and init.defaultBranch main). If you made the
  repository before that, git calls the main line master instead of main. That is fine.
- nano FILE opens a file to edit: ctrl+O then enter saves it, ctrl+X leaves.
- To start this problem again, delete its folder with rm -rf p6_team (-rf also deletes the .git
  folder inside it, and there is no undo).
